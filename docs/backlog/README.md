# Organização do backlog

O projeto adota um backlog Markdown na raiz: [PRODUCT-BACKLOG.md](../../PRODUCT-BACKLOG.md).

## Estados

- **Concluído:** implementado e com a evidência indicada.
- **Em validação:** implementado, mas depende de QA ou homologação.
- **Planejado:** requisito entendido, ainda não iniciado.
- **A esclarecer:** depende de decisão da clínica ou orientação acadêmica.

## Priorização

- **P0:** segurança, perda ou corrupção de dados e bloqueios do atendimento.
- **P1:** fluxo clínico essencial ou inconsistência relevante.
- **P2:** melhoria de produtividade, qualidade ou manutenção.
- **P3:** evolução desejável sem impacto imediato no atendimento.

Cada item deve apontar para requisito, decisão ou justificativa quando aplicável. O backlog não substitui a documentação acadêmica nem transforma uma ideia em requisito aprovado.
